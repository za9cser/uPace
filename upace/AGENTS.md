# uPace

uPace — утилитное React Native / Expo-приложение для беговых расчётов:

- вычисление времени, темпа или дистанции по двум известным значениям;
- расчёт накопительного времени и отсечек по кругам;
- сложение временных отсечек с точностью до десятых секунды;
- копирование результата и списка отсечек в буфер обмена.

Интерфейс приложения сейчас на английском. Единицы расчётов: дистанция — километры, темп — минуты на километр.

## Стек и запуск

- Expo SDK 54, React Native 0.81, React 19, TypeScript в strict mode.
- Маршрутизация: Expo Router 6 с typed routes.
- UI: React Native Paper, Material Icons, `react-native-safe-area-context`.
- Состояние экранных форм: Formik; глобальные providers — тема и Snackbar.
- Пакетный менеджер: npm (`package-lock.json`).

Команды:

```bash
npm install
npm start          # Expo development server
npm run android    # Expo + Android
npm run ios        # Expo + iOS
npm run web        # Expo + Web
npx tsc --noEmit   # проверка TypeScript
```

Скриптов lint и автоматических тестов в `package.json` нет. `lib/paceCalc/services/testLapSplit.ts` — ручной сценарий с `console.log`, а не настроенный test runner. Не добавляй тестовые каркасы без необходимости; если добавляешь тесты в проект с уже настроенным runner, покрой изменённые расчёты, включая граничные случаи.

## Архитектурные соглашения

- Новые экраны размещай в `app/` по соглашениям Expo Router; UI и бизнес-логику не смешивай в route-файлах.
- Формы остаются локальными для экрана и используют Formik. Дочерние компоненты получают состояние через `useFormikContext<...>()` и изменяют его через `setFieldValue` / `FieldArray`.
- Вычисления, парсинг и форматирование держи в `lib/<feature>/services/`; компоненты отвечают за ввод, отображение и вызов этих функций.
- Типы формы держи в `lib/<feature>/types/`, общие доменные сущности — в `types/index.ts`. Не создавай ещё одну параллельную иерархию типов.
- Используй alias `@/...`; он настроен одновременно в `tsconfig.json` и `babel.config.js`. Внутри близко связанных компонентов допустимы относительные импорты, как в существующем коде.
- Используй функциональные компоненты, named interfaces для props, `StyleSheet.create` и существующий стиль двойных кавычек.
- Для цветов и отступов используй `useCustomTheme()`: `theme.colors`, `theme.spacing`, при необходимости `theme.paper`. Не зашивай новые светлые/тёмные цвета без необходимости.
- Общие уведомления показывай через `useSnackbar()`. Не добавляй отдельный глобальный state manager без реальной потребности.
- Состояние сейчас не сохраняется между запусками. Не добавляй storage, backend или зависимости для локальных вычислений без требования задачи.
- Поддерживай существующее поведение numeric inputs: пустое поле представляет ноль, значения ограничиваются диапазоном, ввод числовой. Дистанция вводится строкой и преобразуется через `parseFloat`.

## Доменные правила

### Pace Calculator

Основные функции: `calculateMissingValue`, `handleCalculateField`, `handleFieldChange`.

- Вычисление выполняется только при ровно двух заполненных значениях из трёх: время, темп, дистанция.
- Формулы: `дистанция = время / темп`, `темп = время / дистанция`, `время = темп × дистанция`.
- Внутри расчётов время и темп представлены секундами; дистанция — километрами.
- Автовычисление и явное нажатие кнопки расчёта — разные сценарии; сохраняй оба.
- Ноль или пустые поля считаются отсутствующим значением. Сейчас результаты времени/темпа округляются вниз до целых секунд, дистанция форматируется до двух знаков.

### Lap Splits

Основная функция: `calculateLapSplits`.

- Используются текущие темп и общая дистанция формы плюс длина круга.
- Полные круги рассчитываются накопительно; последний неполный круг добавляется отдельно.
- При неположительных темпе, дистанции или длине круга возвращается пустой массив.
- `totalTime` — накопительное время, `splitTime` — время конкретного круга.

### Time Calculator

Основные функции: `calculateTotal`, `formatResult`, `copyResultToClipboard`, `copySplitsToClipboard`.

- Базовая единица суммирования — десятая секунды (decisecond): минута = 600, секунда = 10.
- Флаги `summaryOptions` определяют, какие компоненты каждой отсечки участвуют в сумме и экспорте.
- Итог всегда форматируется как `mm:ss.d`; минуты не ограничены двумя цифрами по смыслу, несмотря на `padStart(2, "0")`.
- Экспорт списка отсечек зависит от выбранных компонентов. При изменении форматирования проверь все комбинации флагов, а не только полный формат.

## Проверка изменений

1. Запусти `npx tsc --noEmit` и отдели новые ошибки от уже существующих.
2. Проверь сценарий в Expo на затрагиваемой платформе; минимально убедись, что Metro собирает приложение без новых ошибок.
3. Для расчётов вручную проверь обычный и граничные случаи: пустые/нулевые значения, неполный последний круг, переход секунд в минуты, отключённые компоненты суммы.
4. Для UI проверь light/dark mode, клавиатуру и переходы фокуса, длинные результаты и нижние вкладки.

Текущий baseline TypeScript не чистый: есть ошибки ref-типов в `components/paceCalc/PaceInputs.tsx`, неверные импорты `@/types/PaceCalcFormValues` и `@/types/TimeCalcFormValues` в services, а также вытекающие ошибки типизации. Не считай их результатом своего изменения, но не используй baseline как причину оставлять новые ошибки.

## Чего избегать

- Не меняй платформенные идентификаторы, splash, схему приложения и EAS profiles без явной задачи.
- Не выполняй EAS build/submit или другие внешние публикации без запроса пользователя.
- Не дублируй формулы в компонентах; расширяй существующие service-функции.
- Не меняй точность, единицы или формат вывода незаметно — это пользовательски заметное поведение.
- Не добавляй `.agents/` или дополнительные instruction-файлы без отдельной потребности: для текущего небольшого проекта достаточно этого файла.
